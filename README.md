# AI半導体 決算カレンダー

米国でAI関連の設備投資をけん引する会社と、その影響を受ける日本の関連株、**55銘柄**（米国23・日本32）の決算予定日を1つのカレンダーで見られるWebサイトです。半導体だけでなく、AIデータセンターを作るのに必要な基板・光ファイバー・サーバー・電力まで、サプライチェーンに沿って選んでいます。日付は**各社のIRページから自動で集めて**います。

- サイト: https://YOUR_NAME.github.io/earnings-calendar/

日本株で取引する人が多いことを考えて、日本株は関連の深い銘柄を広めに載せています。SKハイニックス（韓国）は米国ADRとして載せています。

分野と市場で絞り込めます（選んだ条件は次に開いたときも残ります）。

## なぜ作ったか

<!-- TODO: 自分の言葉で書き足す -->
証券会社などの決算カレンダーは、業種で絞り込めないなど使いにくいと感じていました。また半導体株では、**エヌビディアなど米国の決算が、日本の製造装置株の値動きに影響する**ことがよくあります。米国と日本の関連銘柄を並べて、分野ごとに見られるカレンダーを作りました。

## 仕組み

```
GitHub Actions（毎月15日と28日）
  └ scraper/update.py が companies.json の各社IRページを取得
      ・robots.txt を守り、1ページごとに3秒あける
      ・JavaScriptで表示するページ（11社）はヘッドレスブラウザで表示してから読む
  └ scraper/extract.py が決算の日付を取り出す
  └ docs/data/earnings.json を更新してコミット
      └ GitHub Pages の画面（docs/）がそのJSONを読んで表示
```

サーバーもデータベースも使わず、無料の範囲でいつでも誰でも見られる構成にしました。

## 画面

ライブラリを使わないHTML・CSS・JavaScriptだけで作っています。URLの `#week` `#month` `#map` `#list` で4つの表示を切り替えます。

- **週間**: 直近の確定決算（あと何日）と、月〜金の5列ボード。日本株と米国株に分けて表示
- **月間**: 日ごとの件数と主な銘柄。日付を押すと右にその日の全銘柄
- **業界マップ**: AIのサプライチェーン（買う → つなぐ・動かす → 頭脳と記憶 → つくる）に沿ってカテゴリを並べ、選んだカテゴリの各社の次回決算を3か月先までのタイムラインで表示
- **銘柄一覧**: 掲載銘柄と、各社IRページの自動取得が成功しているか

確定（会社発表）・予想（前年同期から推定）・時期のみ（上旬・中旬・下旬）・発表済みを、どの画面でも同じバッジで区別しています。市場とカテゴリの絞り込みはブラウザに保存され、次に開いたときも残ります。

## 設計で判断したこと

| 課題 | 判断 |
|---|---|
| データの出どころ | 有料のデータAPI（J-Quants）は「取得データの閲覧可能な形での再配布」が規約で禁止されているため使わない。**一次情報である各社IRページ**から日付という事実だけを取り、必ず出典リンクを付ける |
| ページの書き方が会社ごとにばらばら | 55社のIRページを実際に調べ、書き方を4つの形に整理した（下の表）。会社ごとの専用コードは作らず、共通の取り出し処理＋会社ごとの設定（`companies.json`）にした。銘柄を増やすときは設定を足すだけ |
| JavaScriptで後から表示するページ | IR制作会社の部品を直接呼ぶのではなく、**会社自身のページを人と同じようにブラウザで表示してから読む**（`render: true`）。データの出どころを一次情報のままにするため |
| ニュース一覧の「掲載日」を誤って拾う | キーワードと同じ行の日付だけを使い、「決算発表**は**」「conference call **on**」のようにつながっている時だけ結び付ける |
| 年が書かれていない日付（10月28日） | ①同じ行の対象期間（「2026年3月期 第3四半期」なら2025年12月末より後）②表の年見出し（2026／2026年度）③同じ文の年つき日付（"which ended April 26, 2026"）④今日に近い年、の順で決める。日立のように通期決算を前の年度の見出しの下に載せるページがあるため、対象期間を最優先にした |
| 同じ日に決算発表と説明会・電話会議が並ぶ | 「決算発表」の行の時刻を優先する（味の素）。説明会が翌日にある場合（日本マイクロニクス）は、決算発表の日だけを残す |
| 「2026年 4月 4月28日」のような表 | 年月日の形は「日」まで書かれているときだけ日付とみなす（TDK） |
| カレンダーが画像や他社の埋め込み部品 | 読めないので、IRニュースの決算資料の掲載日を実績として使い、次回は推定にする（三菱電機、レゾナック） |
| 銘柄の入れ替え | 買収が決まった会社は外す（ルメンタムはマーベルによる買収が発表されたため、光部品はコヒレントにした） |
| 「1月下旬」のように時期だけ発表 | 日付と区別して「1月下旬（会社発表・日付は未定）」と表示 |
| 取得に失敗したら | 前回の値を残して表示し、「取得状況」に失敗と出す。1社の失敗でサイト全体の更新は止めない |
| まだ日程が出ていない | 過去の実績から「前年同期と同じ曜日」または「前回の約3か月後」を**推定**として点線で表示。土日・日本の祝日に当たったら前の営業日にずらす |
| 米国株の時差 | 時刻が分かるものは**日本時間の日付**に置く（米国の夕方の発表は日本では翌朝） |
| サイトの作り変えに気づけるか | 2026年11月に55社のページを実際に開いて保存したテキストでテスト（`tests/fixtures/`）。期待する日付は人の目で確認して書いた |

### 実際に見つかったページの書き方

| 形 | 例 | 会社の例 |
|---|---|---|
| キーワード→日付の文 | 「決算発表は10月28日」「financial results on Wednesday, October 28」 | エヌビディア、アルファベット |
| 日付→項目名が1行 | 「2027.02.05 第3四半期決算発表（予定）」 | 東京エレクトロン、SCREEN、信越化学 |
| 日付だけの行と項目名の行（日付が先） | 「Nov 3, 2026 • 2:00 pm PST」→「AMD … Financial Results」 | AMD、KLA、TSMC、キオクシア |
| 同（日付が後） | 「… Earnings Conference Call」→「OCT 21, 2026 AT 2:00PM」 | ラムリサーチ、マイクロソフト |

## 自分のPCで動かす

```bash
pip install -r requirements.txt pytest
python -m playwright install chromium   # JavaScriptで表示する11社のため
pytest -q                               # 取り出し処理のテスト（ネット接続なしで動く）
python -m scraper.update --dry-run      # 実際に取得して結果を表示（ファイルは書き換えない）
python -m scraper.update                # 取得して docs/data/earnings.json を更新
cd docs && python -m http.server        # http://localhost:8000 で画面を確認
```

## 日付が正しいかを J-Quants で確かめる（自分のPCだけで）

日本株の決算日を、J-Quants の「決算発表予定日」（`/v2/fins/earnings-date`）と突き合わせて、一致・不一致・取りこぼしを一覧にします。J-Quants のデータは規約上公開できないので、**照合結果（`verify_report.md`）はコミットしない**でください（`.gitignore` 済み）。サイトに載せる日付はこれまでどおり各社のIRページから取ります。

```powershell
$env:JQUANTS_API_KEY = "ダッシュボードで発行したAPIキー"
python scripts/verify_jquants.py
```

判定は「✅ 一致／❌ 不一致／会社発表あり（推定のままになっている）／⚠ カレンダーに無い予定日」などです。米国株は J-Quants に無いため対象外です。

## 銘柄を追加する

`companies.json` に1社分を足します。`sources` は上から順に試され、日付が取れた時点で止まります。

| 設定 | 意味 |
|---|---|
| `render: true` | JavaScriptで表示するページ。ブラウザで表示してから読む |
| `follow: "文字列"` | 一覧ページの中でリンク文字が一致する記事（最大3件）も読む（決算日の告知記事など） |
| `date_line: "after"` | 日付だけの行が項目名の**後**に来るページ（初期値は `before`） |

追加したら、そのページの内容を `tests/fixtures/` に保存して期待する日付をテストに書いておくと、サイトが変わったときに気づけます。

## 公開の手順（GitHub）

1. このフォルダをGitHubの新しいリポジトリにpushする
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/docs` にする
3. Actions タブ →「決算予定日の更新」→「Run workflow」で初回の取得を実行し、ログが全社 `[OK]` か確認する
4. `scraper/fetch.py` の `USER_AGENT` と `docs/index.html` の GitHub リンクの `YOUR_NAME` を自分のものに変える
